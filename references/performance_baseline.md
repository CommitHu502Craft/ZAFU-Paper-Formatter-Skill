# 性能、正确性与视觉验证记录

本文及所链接 JSON 保存的是页眉、封面保护与缺项规则本次修订前的测量和审阅结果，不作为当前操作指令或当前测试通过率。当前行为以 [SKILL.md](../SKILL.md) 为准；历史记录不回写，模板空白字段也不再视为需要填写的缺项。

## 测量方法与范围

环境为 Windows 11、Python 3.12.12（uv 项目环境）。优先采用仓库已有四个输入；输入 SHA256、完整阶段时间、调用次数、退出码和质量门保存在本目录的 [原始基线](benchmarks/before.json) 与 [重构后记录](benchmarks/after.json)。基线在重构前测得，保留当时工作区已有修改；补充视觉基线与回归时使用隔离的原始执行链副本，没有覆盖当前源码。

每组各一次 cold/warm，不是统计分布或性能保证。cold 是新输出目录、无项目模板缓存；warm 是独立进程再次执行、复用模板缓存。没有清空系统磁盘缓存，也不保证 Word 服务处于冷启动。最终重测顺序执行，不与回归任务并发。计时打开了 Python profiler，绝对耗时含其开销。

进程数为 Python 审计钩子捕获的显式外部进程启动数，不包括操作系统或 COM 隐式启动的服务。阶段为包含子调用的累计时间，解析、模板和验证时间有重叠，不能相加。未运行阶段记为缺项，不能解释为 0 秒。视觉修复轮数在这些性能样例中均为 0；性能数据不包含人或 Agent 看图所需时间。

## 四类样例：相同 structural 检查

单位为秒，冷/热均为实际端到端时间。显式 `--check structural` 在两版含义一致，避免把重构后的 Final 渲染与旧版无渲染流程混比。

| 样例 | 修改前冷/热 | 修改后冷/热 | 外部进程前→后 | 质量门前→后 |
|---|---:|---:|---:|---|
| A 清晰 Markdown | 16.930 / 16.736 | 7.758 / 6.673 | 13 → 0 | 通过 → 通过 |
| B 基本正常 DOCX | 19.760 / 17.620 | 4.718 / 4.232 | 12 → 0 | 通过 → 通过 |
| C 混乱 DOCX | 18.044 / 17.903 | 5.213 / 4.664 | 12 → 0 | 硬失败 → 同类硬失败 |
| D 图片与复杂结构 DOCX | 17.533 / 17.756 | 5.116 / 4.396 | 12 → 0 | 通过 → 通过 |

输入路径由基准脚本固定：A 为 `unified_markdown/input.md`，B 为 `profiles/hybrid_fixture/template.docx`，C 为 `tests/samples/messy_student_thesis.docx`，D 为 `docx_hybrid_mixed_confidence_assets/input.docx`。D 实际含六个 drawing 和六份媒体资源，不将它冒充为脚注、OLE 或复杂公式的端到端覆盖。

C 在当时测量的两版中均因 `missing_header_footer_parts` 拒绝交付；当时的保守路径未创建缺失页眉页脚。这是历史行为，当前规则要求为可识别正文/摘要节补齐缺失页眉。该速度记录代表当时运行至拒绝交付的耗时，不是成功交付耗时。

A 的解析调用由 15 次降至 3 次；DOCX 样例由 19 次降至 4 次，计数包含模板内部解析及最终验证视图，并非全部解析同一个输入。模板提取冷运行由 6–8 次降至 1 次，热运行为 0 次。完整的安全验证仍然执行。

## 测试与现存失败

- 重构前 75 项单元测试通过；修改后 90 项通过，含共享 IR、双后端无编译生成、安全规范化、资产丢失阻断、批注范围保护、缓存失效、短标题锚点、歧义与冲突处理、原生公式保护及审阅证据检查。
- 历史兼容回归执行 24 项、跳过 1 项：修改前后均为 10 项通过、14 项失败；逐项 mismatches 完全一致。运行器显式选择 `--pipeline legacy`，保留历史诊断字段断言，未改预期结果来掩盖失败。可查看 [完整比较](benchmarks/regression_comparison.json)。
- 既有失败包括参考文献/公式/手动编号样例的硬失败、三组 hybrid 样例未经结构授权而未重建、纯文本枚举的旧停止状态假设。它们仍需单独修复，不能宣称回归全通过。
- Word COM 实际完成 A 的 PDF 导出、目录更新及 5 页预览。已实际查看总览和全部 5 张关键 PNG：发现并修复了“重用分节结束段落导致标题与正文分离”的问题，并新增单元测试。最后候选标题和正文已同页，表格没有观察到截断或文字重叠。
- 此样例仍有封面信息空缺、缺英文摘要、封面/声明页码与正文首页页眉待规范核对。已写入真实审阅记录，状态为 `reviewed_with_issues` / `candidate_with_visual_issues`，没有标为完全验收。脱敏的 [审阅证据](benchmarks/visual_review_example.json) 保留候选和图片哈希。
- WPS、LibreOffice 真实转换及 LaTeX 完整编译未验证；LaTeX 仅验证无编译工程生成和相关单元测试。

## 复现

在仓库根目录执行，输出 label 必须为新的目录名：

```powershell
uv run python scripts/benchmark_pipeline.py --output-dir D:/formatter-benchmarks --label trial
uv run python scripts/benchmark_pipeline.py --output-dir D:/formatter-benchmarks --label trial-visual --check visual --cases A_markdown
uv run python -m unittest discover -s tests -v
uv run python scripts/run_regression_fixtures.py --output-dir D:/formatter-regression
```

基准不会把非零退出码隐去；它将每例退出码写入结果，C 的失败是预期观察而非忽略。图片审阅要按 [视觉验收说明](optional_visual_review.md) 独立完成，重新运行不自动继承旧审阅。

记录当时的限制：文本路线仍有构建暂存 DOCX 与一次模板落地，未做到单次 ZIP 写入；视觉几何仅是提示；复杂原生区域保留不等于合规。当时待处理的学校模板页眉页脚问题及 14 项回归失败，不能直接用作当前版本的失败清单，须以重新执行的结果为准。
